## Fix 1: FIB786 was firing duplicate alerts
pollCycle() in artifacts/api-server/src/lib/fib786-notifier.ts was scheduled with setInterval(fn, 60_000), which doesn't wait for the previous call to finish. Since pollCycle loops sequentially over the full tracked-symbol universe with a network await per symbol, a single cycle could take longer than 60s, so multiple cycles ran concurrently. Two overlapping cycles could both see "no active alert yet" for the same symbol (the lock from setActiveAlert hadn't been written yet by the still-running cycle) and both fire — this produced 10 duplicate RENDERUSDT closed-trade rows in production sharing one firedAt timestamp. Fixed by switching to a self-scheduling setTimeout loop (only reschedules after the previous cycle fully resolves) plus a re-entrancy guard.
## Fix 2: no way to actually see FIB786 signals in the UI
FIB786 is alert-only (never places real orders), so it was never going to show up in the P&L tab's "Filled Positions"/"Pending Limits" panel — that panel only reflects real Phemex/MT5 fills. There was no UI anywhere showing FIB786 activity, even though the /api/fib786-history endpoint existed.
Added a new "FIB786" tab to the dashboard (artifacts/xagusd-screener/src/pages/dashboard.tsx, new component artifacts/xagusd-screener/src/components/fib786-panel.tsx) that reads /api/fib786-history directly and shows: real win rate / total R / open-alert count, a list of open alerts with entry/stop/TP1/TP2 and fill state, and a list of closed trades with outcome and R multiple. Auto-refreshes every 30s.
