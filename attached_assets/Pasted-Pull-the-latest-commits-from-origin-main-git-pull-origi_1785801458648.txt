## 1. Retired unprofitable/broken signal types (in artifacts/api-server/src/lib/signals.ts and notifier.ts)
- FIB50_SWING: removed entirely (detection code deleted, removed from the real Phemex auto-trade allowlist and all alert gates).
- PRICE_ACTION_SR: disabled via a boolean kill-switch (PRICE_ACTION_SR_ENABLED = false). Real trade history showed 91 trades, -24.6R, ~90% of all trade volume — the single worst offender.
- SWING_BREAK: disabled (SWING_BREAK_ENABLED = false). -9.0R over 64 real trades.
- BB_BREAKOUT: disabled (BB_BREAKOUT_ENABLED = false). -14.75R over 27 real trades.
- DOUBLE_TOP: disabled (DOUBLE_TOP_ENABLED = false). This one had an actual math bug — its TP1 stop/target formula made reward structurally always less than risk, so its 1.5R gate could never pass. Fixed the formula (now uses floorTarget like DOUBLE_BOTTOM already did), backtested with the fix, and it produced 16 real trades at only 12.5% win rate / PF 0.21 — confirmed no real edge, so it's disabled too even though the bug is fixed.
- BB_REJECTION is the only signal type left in the real-money auto-trade allowlist (DEFAULT_ALLOWED_SIGNAL_TYPES in notifier.ts) — it's the only one that showed a genuine positive edge (66.7% win rate, PF 4.00, small sample).
Net effect: DEFAULT_ALLOWED_SIGNAL_TYPES went from "FIB50_SWING,BB_REJECTION,DOUBLE_BOTTOM,DOUBLE_TOP" to just "BB_REJECTION,DOUBLE_BOTTOM" (DOUBLE_BOTTOM essentially never fires in practice, so real trading activity should drop close to zero until BB_REJECTION is validated further or FIB786 below is trusted more).
